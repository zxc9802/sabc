# SABC 连续访谈、外部调研与最终报告设计

- 状态：设计已确认，待实施计划
- 日期：2026-07-22
- 目标目录：`D:\SABC智能体新`
- 默认问答深度：中

## 1. 背景

当前实现会在每轮用户回答后先执行一次结构化评级，再调用模型流式生成解释和下一问。右侧评级随每轮对话更新。这使一次普通对话包含两次模型工作，首字延迟明显，也把用户注意力从持续访谈带到了尚未成熟的临时分数上。

本次改造把访谈与评级彻底分离：访谈阶段只进行一次真正的流式 AI 对话；用户确认结束后，系统才提炼公开搜索词、调用 AnySearch 调研、把搜索结果返回给 AI 做最终分析，并且只在最后运行一次确定性评分和报告生成。

## 2. 目标与非目标

### 目标

- 用户与 AI 在同一聊天区持续交流，每轮生成内容立即显示。
- 访谈阶段不生成、保存或展示评级，避免每轮评分造成的延迟。
- 保留低、中、高三档问答深度，默认使用中档。
- AI 在信息充分时可以建议结束访谈，但不能自动结束。
- 只有用户点击“结束访谈并开始调研”后，系统才进入外部调研阶段。
- AnySearch 只接收从访谈中提炼出的公开搜索语句，不接收完整聊天记录或敏感经营原文。
- AnySearch 返回的标题、摘要、来源链接和必要正文必须先交给 AI，AI 再结合完整访谈完成最终分析。
- 七维评分规则只执行一次，最终报告同时包含访谈事实、外部证据和可访问的来源链接。
- 调研或最终生成失败时保留全部聊天记录，并支持从失败阶段恢复。

### 非目标

- 不改变现有七维权重、等级阈值、证据上限和否决规则。
- 不让 AnySearch 或模型直接决定程序计算的总分和等级。
- 不在访谈过程中后台评分或更新隐藏评分。
- 不把 API Key、模型思维过程、供应商原始错误体或完整敏感访谈发送到浏览器或第三方搜索服务。
- 不重做项目索引、项目对比、打印和 PDF 导出能力。

## 3. 已确认的产品决策

1. 采用“连续访谈 → 用户结束 → 外部调研 → AI 最终分析 → 一次评分 → 最终报告”的串行流程。
2. AI 可以建议结束，但结束动作始终由用户点击按钮触发。
3. AI 的结束建议属于当前流式聊天回复，不增加独立评分或完整度判定请求。
4. 访谈期间不显示临时等级、总分、置信度或七维评分。
5. 调研仅在用户结束访谈后自动开始，不在聊天过程中提前调用 AnySearch。
6. AnySearch 搜索结果必须返回给最终分析模型，模型不得在调研完成前生成最终结论。
7. 最终结构化分析完成后，TypeScript 评分引擎才运行一次。
8. 调研关键词只包含公开主题，不包含完整对话、密钥、联系方式或可识别的内部敏感原文。

## 4. 方案比较

### 采用：结束后集中调研和评级

访谈每轮只有一次流式模型调用。结束后执行一次完整调研和报告流水线。该方案让日常聊天最快，阶段边界清楚，也最符合“先把事实问清楚，再一次性形成结论”的产品目标。代价是用户点击结束后需要等待调研与最终分析完成。

### 未采用：聊天期间后台调研

该方案可能缩短最终报告等待时间，但会在项目范围尚未明确时发送低质量搜索词，增加请求成本和隐私风险，也引入缓存失效与结果合并逻辑。

### 未采用：用户手动选择调研内容

该方案控制力更强，但把搜索规划工作转交给了用户，破坏自然访谈体验，也不符合自动调研的目标。

## 5. 用户体验

### 5.1 访谈阶段

- 项目创建后，初始描述作为第一条用户消息保存，服务端立即开始流式生成 AI 回复。
- 后续所有补充都使用同一输入框，AI 每次只追问一个最关键的问题。
- 不再显示“正在核对证据与评分规则”，改为与聊天一致的“正在思考”或“正在生成”。
- 移除访谈页面右侧的逐轮评级面板，让聊天区使用释放出的宽度。
- 问答深度仍可切换为低、中、高，切换从下一轮回复开始生效。
- “结束访谈并开始调研”按钮在已有有效访谈后可用，旁边明确说明点击后会提炼公开关键词并联网调研。

### 5.2 AI 建议结束

AI 根据当前问答深度判断是否仍有高价值缺口：

- 低档关注项目目标、目标用户、问题、已有验证、主要资源与关键风险。
- 中档进一步覆盖七个评价维度中的核心事实，并把无法回答的关键信息明确标记为未知。
- 高档继续核实数据来源、时间、金额、样本、计算过程、矛盾点和风险应对。

当相应深度下的核心信息已经充分，或剩余问题无法显著改变结论时，AI 在同一次自然语言回复中说明：“核心信息已经比较完整，建议结束访谈并开始调研；你也可以继续补充。”这只是建议，不触发状态迁移。用户可以继续交流，也可以点击结束按钮。

### 5.3 调研与最终生成阶段

点击结束后，聊天输入暂时锁定，页面在聊天尾部展示阶段进度：

1. 提炼公开调研关键词；
2. 联网调研；
3. 整理外部证据；
4. AI 综合分析；
5. 计算最终评级；
6. 保存并打开报告。

每个阶段只显示用户可理解的状态，不显示内部提示词、模型思维过程或 API 载荷。成功后自动进入最终报告页。

## 6. 系统架构与数据流

### 6.1 访谈接口

`POST /api/chat` 取代访谈阶段现有的逐轮分析职责。请求包含项目描述、已保存消息和问答深度，响应使用 `text/event-stream`：

- `assistant_delta`：模型新生成的文字片段；
- `complete`：完整 AI 消息及消息标识；
- `error`：稳定错误码、可读说明和是否可重试。

该接口不调用结构化分析、不执行评分引擎，也不产生 `assessment` 事件。服务端提示词要求 AI 认真确认用户回答、指出尚缺信息、每次只问一个问题，并在信息充分时自然建议结束。

### 6.2 最终化接口

`POST /api/finalize` 负责调研和报告编排，同样通过 SSE 返回阶段进度。服务端严格按以下顺序执行：

```text
完整访谈
  → 提炼并清洗公开搜索语句
  → AnySearch 搜索与必要页面提取
  → 标准化外部证据
  → 把完整访谈 + 外部证据交给 AI
  → 校验 AI 结构化分析
  → TypeScript 规则评分一次
  → 生成并保存最终报告
```

关键约束：最终 AI 分析调用必须发生在 AnySearch 结果已返回并完成标准化之后。测试必须能够证明最终模型请求中包含实际搜索结果，而不是仅包含搜索词、搜索状态或模型自行猜测的摘要。

最终化接口按顺序发送以下事件：

- `status`：`planning_research`、`researching`、`analyzing`、`scoring` 或 `saving`；
- `research_plan`：已完成敏感信息清洗的公开搜索语句；
- `research_complete`：标准化来源和调研状态；客户端收到后立即保存调研快照；
- `assessment`：完成结构校验和规则评分后的唯一最终评估；
- `complete`：已生成并保存的报告标识；
- `error`：失败阶段、稳定错误码、可读说明和是否可重试。

如果请求在 `research_complete` 之后失败，重试请求可以携带已保存的调研快照并从 `analyzing` 继续。服务端必须重新校验快照结构、数量和 URL；未通过校验时重新执行调研，不能把任意客户端文本直接提升为外部证据。

### 6.3 AnySearch 服务端客户端

产品运行时不依赖 Codex 本机 Skill 目录或 CLI 进程。新增独立的服务端 AnySearch 客户端，直接调用官方 JSON-RPC 接口。这样本地开发、测试和部署使用同一代码路径。

客户端只读取服务端环境变量 `ANYSEARCH_API_KEY`。密钥不得出现在 `NEXT_PUBLIC_*` 变量、客户端组件、SSE 事件、日志或 IndexedDB 中。

一次最终化最多生成 5 条搜索语句。每条语句经过清洗后再发送。搜索结果标准化为：

- 标题；
- 摘要；
- 原始 URL；
- 来源名称；
- 与项目判断的相关性；
- 必要时提取的正文片段；
- 调研时间。

正文提取必须限制单页长度和总上下文大小，优先保留与决策相关的片段，避免把无限页面内容直接塞入模型上下文。

### 6.4 最终 AI 分析与评分

最终模型输入由两块明确隔离的资料组成：

1. 用户访谈记录，标记为用户提供且尚需核实的材料；
2. AnySearch 返回并标准化的外部证据，保留标题和 URL 以便引用。

模型负责提取事实、证据、风险、类别、信息缺口和行动建议，并在每项外部事实上保留来源引用。模型不能直接设置程序最终分数。

结构化结果通过现有 schema 校验后，现有 TypeScript 评分引擎应用七维权重、置信度、等级阈值和否决规则。该评分函数在一次最终化中只能调用一次。

## 7. 状态与持久化

工作区阶段调整为：

```text
idle → chatting → ready
              ↘ stopped → ready
ready → planning_research → researching → analyzing → scoring → saving → report
                                      ↘ failed → retry/fallback
```

- 用户消息在聊天请求开始前保存，流式完成后保存完整 AI 消息。
- 访谈期间不创建 `AssessmentRecord`。
- 新增项目级调研快照记录，保存已清洗查询、标准化来源、调研状态和更新时间。调研状态为 `completed`、`partial` 或 `unavailable`。
- 客户端收到 `research_complete` 后先保存调研快照；最终化成功后再保存唯一的最终 `AssessmentRecord` 和 `FinalReportRecord`。
- 项目切换或组件卸载时取消当前请求，并忽略迟到流事件。
- 最终化失败时保留消息和已保存的调研快照；调研已完成时从分析阶段重试，调研未完成时从搜索阶段重试。
- 报告保存成功后才将项目标记为可比较的最终项目。

## 8. 最终报告

最终报告保留现有打印和 PDF 入口，并包含：

- 投资或项目优先级建议；
- 最终等级、总分、置信度和七维评分；
- 访谈确认的事实与仍未验证的用户声明；
- 外部调研发现，每条带来源标题和可点击 URL；
- 机会、风险、否决项和关键未知；
- 下一步验证动作与升级条件；
- 简明访谈摘要。

报告必须区分“用户陈述”和“外部来源”。没有来源 URL 的内容不得标记成外部调研证据。

## 9. 隐私与安全

- 搜索规划模型只输出公开查询语句，不输出访谈摘要全文。
- 清洗器拒绝或移除 API Key、访问令牌、密码、邮箱、电话号码以及明确标注的内部敏感原文。
- 业务名称、公开产品类别、公开地区、公开竞品和公开市场问题可以进入搜索词。
- AnySearch 只接收清洗后的搜索词和需要提取的公开 URL；完整聊天只发送给已配置的最终分析模型。
- API Key 仅保存在未跟踪的服务端 `.env.local` 或部署环境变量中。
- 客户端密钥检查必须覆盖 AnySearch 变量和常见密钥前缀。

## 10. 错误处理

- **聊天模型失败**：保留已保存的用户消息，显示可重试错误；不创建任何评分记录。
- **用户停止流式生成**：保留已显示内容并恢复输入，允许继续聊天或重新生成。
- **搜索计划无效**：执行一次结构修复；仍无效时停止最终化并给出可重试说明。
- **AnySearch 临时失败**：自动重试一次，仍失败时明确显示“外部调研未完成”。
- **调研不可用**：用户可以重新调研，或选择“仅依据访谈生成报告”。后者的报告必须标记 `researchStatus: unavailable`，不得生成伪造来源。
- **部分搜索成功**：把成功结果交给 AI，同时在报告中列出未完成的查询和证据限制。
- **最终结构化分析失败**：保留已校验的调研快照，从分析阶段重试，不重复搜索。
- **本地保存失败**：结果保留在内存中并提供重新保存；不得把未保存项目标记为最终完成。

## 11. 测试与验收

实施采用测试先行，先写失败测试，再做最小实现。

### 单元测试

- 访谈提示词按低、中、高档调整追问深度，默认值为中。
- AI 可以建议结束，但聊天完成事件不会自动进入最终化状态。
- 搜索语句清洗会移除密钥、联系方式和内部敏感原文。
- AnySearch 响应能够标准化为带标题、摘要和 URL 的来源。
- `research_complete` 到达后会先持久化调研快照，再处理最终评估事件。
- 最终模型输入同时包含完整访谈和真实标准化搜索结果。
- 最终模型调用发生在调研完成之后。
- 重试时只有通过 schema 与 URL 校验的调研快照可以跳过重复搜索。
- 一次最终化只调用一次评分函数。
- 调研不可用时不会生成伪造来源。

### API、reducer 与组件测试

- `/api/chat` 只产生聊天流事件，不产生 `assessment` 事件。
- 多个 `assistant_delta` 会立即追加到同一条可见消息。
- 访谈每轮不会保存 `AssessmentRecord`，右侧评级面板不再出现。
- AI 建议结束后用户仍可继续发送消息。
- 只有点击结束按钮才请求 `/api/finalize`。
- 最终化阶段按顺序显示搜索、分析、评分和保存进度。
- AnySearch 成功、部分成功、超时、重试失败和仅按访谈生成路径均可恢复。
- 最终报告保存后刷新仍可打开，外部证据链接仍然存在。
- 项目列表、删除、对比、打印和 PDF 相关行为无回归。

## 12. 成功标准

只有同时满足以下条件才算完成：

1. 访谈阶段每轮只有一次流式聊天调用，不执行评级。
2. 用户可以持续交流，AI 只在合适时建议结束，结束权始终属于用户。
3. AnySearch 只接收清洗后的公开搜索语句。
4. 搜索结果先返回给 AI，AI 再结合访谈完成最终分析。
5. 评分规则仅在最终分析完成后运行一次。
6. 最终报告清楚区分用户陈述与外部证据，并保留来源链接。
7. 搜索、分析或保存失败不会丢失访谈，也不会伪造调研结论。
8. 自动化检查和真实浏览器端到端验证全部通过。
