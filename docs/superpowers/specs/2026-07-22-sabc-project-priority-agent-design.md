# SABC 项目投入优先级智能体设计

- 状态：已确认
- 日期：2026-07-22
- 目标目录：`D:\SABC智能体新`
- 目标用户：需要比较和筛选项目投入优先级的小团队管理者
- 首版语言：中文

## 1. 产品目标

应用把自由格式的项目描述转化为可追溯的 S/A/B/C 投入建议。模型负责识别项目类型、提取事实与证据、发现风险并提出追问；纯 TypeScript 评分引擎负责固定权重、证据上限、置信度、等级门槛和一票否决，模型不能直接决定最终等级。

首版支持临时评级、最多六轮的单问题追问、历史项目、本地对比、不可变报告快照和浏览器打印 PDF。业务数据只保存在当前浏览器的 IndexedDB 中，服务端只承担模型请求边界。

## 2. 已确认范围

### 包含

- 在 `D:\SABC智能体新` 根目录重新创建 Next.js 应用。
- 自由文本项目输入和自动类型识别。
- 七个固定一级维度、类型化证据槽位和确定性评分。
- 临时等级、总分、置信度、风险、信息缺口及一次一个的追问。
- 每轮评级快照和确定性的变化解释。
- 当前浏览器中的历史项目和最多四个项目对比。
- 最终或临时报告快照及 A4 打印样式。
- DeepSeek Chat Completions 服务端调用、结构校验、联网能力降级和密钥扫描。
- 单元测试、组件测试、端到端测试、代码检查和生产构建。

### 不包含

- 用户账号、权限、云数据库或跨设备同步。
- 文档上传、团队协作、第三方工作流集成。
- 自动改变评分权重、阈值或否决规则。
- 外部搜索服务商或服务端 PDF 引擎。

## 3. 实现方向

采用“全新工程 + 选择性参考”方案：在当前根目录创建新的 Next.js 工程，按照原始 PRD 的任务顺序重新实现；相邻目录中的旧工程只用于核对接口和已知处理方式，不整体复制。每项生产行为先由失败测试定义，再编写最小实现并验证。

## 4. 架构与边界

### 页面层

负责项目案卷索引、对话、实时评级、比较和报告。页面只消费明确的领域对象，不包含评分、提示词、模型传输或原始 IndexedDB 事务。

### 状态层

使用显式 reducer 和会话 hook 管理加载、提交、失败、重试、保存、恢复、完成报告以及过期响应。新结果必须先尝试持久化，再显示保存成功；保存失败时保留可查看结果并持续标记“结果尚未保存”。

### 业务层

纯 TypeScript 模块定义领域类型、评分目录、证据上限、加权分数、置信度、等级门槛、否决规则、评级差异和追问优先级。该层无浏览器、网络和模型依赖。

### 数据层

Dexie 管理 Project、Message、Assessment、Evidence 和 FinalReport。跨表写入使用事务；最终报告保存不可变评级快照；删除项目时只删除该项目的相关记录。

### 服务端层

Next.js Route Handler 校验输入，在 server-only 模块中读取 `DEEPSEEK_API_ENDPOINT`、`DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL`。默认调用 `https://api.deepseek.com/chat/completions` 上的 `deepseek-v4-pro`，启用 thinking、high reasoning effort、非流式响应和 JSON Output。DeepSeek 接口本身不被当作联网查证来源；模型生成的网址一律不能升级为已验证证据。只有用户明确提供的可复查材料或未来接入的真实工具结果才能成为已验证外部来源。

## 5. 核心数据流

1. 用户提交项目描述。
2. 客户端创建草稿项目和用户消息，并调用分析 API。
3. 服务端将项目文本作为不可信数据交给模型，解析结构化事实、维度建议、证据、否决风险和追问候选。
4. 评分引擎应用证据上限、权重、置信度、等级阈值和否决规则。
5. 客户端以事务保存消息、评级快照和证据，再呈现临时或最终结果。
6. 用户每次回答一个问题；系统保存新快照并用确定性差异说明变化。
7. 用户完成评估时保存不可变报告快照，可比较或通过打印对话框导出 PDF。

## 6. 评分和追问规则

七个一级维度及权重保持固定：战略价值 20、需求证据 20、收益潜力 15、执行可行性 15、资源匹配度 15、时机与差异化 5、风险可控性 10。

证据状态为 missing、general_claim、specific_unverified、verified，对应置信度值 0、0.35、0.70、1.00，并把维度最高分限制为 1、2、4、5。总分为七个维度的加权百分制结果。原始等级门槛为 S≥85、A≥70、B≥50，否则 C；置信度低于 80 不能最终定为 S，低于 65 不能最终定为 A。经用户明确确认或可靠来源验证的一票否决直接得到 C；证据不足时只能标记疑似风险并优先追问。

每轮只选择一个未问过的问题，依次按疑似否决、预期影响、维度权重和稳定 id 排序。默认最多主动追问六轮，用户可以随时按当前信息生成临时报告。

## 7. 视觉系统

主题为“项目决策案卷”，避免通用深色科技控制台。页面的单一任务是帮助管理者把模糊项目转化为可核查的投入判断。

### 颜色

- 纸白 `#F4F7FA`：页面底色。
- 墨蓝 `#15243B`：正文和主要结构。
- 决策蓝 `#2457D6`：主操作与当前选择。
- 批注红 `#D84A3A`：否决风险和错误。
- 证据绿 `#327A5F`：已验证信息和通过状态。
- 警示黄 `#B87916`：临时状态和待验证信息。

### 字体

标题使用宋体风格字栈，形成评审文件的权威感；正文使用微软雅黑风格无衬线字栈；分数、置信度、日期和规则版本使用等宽字栈。所有字体提供 Windows 可用回退，不依赖运行时远程字体下载。

### 布局

桌面端为三栏：左侧项目案卷索引，中间项目描述与逐轮询证记录，右侧固定评级批注栏。窄屏按当前评级、对话、历史项目组织，并将历史列表收纳为抽屉。

```text
┌──────────── 项目决策台 ─────────────┐
│ 案卷索引 │ 项目描述 / 逐轮追问 │ 评级批注 │
│ 草稿     │ 用户事实             │   A     │
│ 临时评级 │ AI 追问              │  76分   │
│ 已完成   │ 变化原因             │ 置信68% │
└──────────────────────────────────────┘
```

### 标志性元素

“证据脊柱”把七个评分维度组织成纵向证据链，每节同时表达维度权重、得分和证据强度，让用户区分“分高但证据不足”与“分数变化来自哪里”。它是评分逻辑的直接视觉映射，不作纯装饰。

动效只用于新评级进入时从旧证据状态过渡到新状态；其他区域保持安静，并完整尊重 `prefers-reduced-motion`。

## 8. 组件边界

- `ProjectWorkspace`：组合会话、历史、对话和评级区域。
- `ProjectList`：项目选择、状态、删除和比较入口。
- `ConversationPanel`：项目描述、消息、快捷回答和提交。
- `AssessmentPanel`：等级、总分、置信度、证据脊柱、风险和变化说明。
- `ComparisonView`：最多四个不可变评级快照的语义化比较。
- `ReportView`：固定报告章节和打印操作。
- `ErrorBanner`：明确错误、重试操作和未保存状态。

组件通过 props 接收领域对象和回调，不读取环境变量，不计算评分，也不直接执行数据库事务。

## 9. 异常处理

- 模型或网络失败：保留用户输入、项目和上一次成功评级，允许重试且不重复消息。
- 模型格式错误：服务端只纠正一次；仍失败时返回安全、可操作的错误。
- 联网查证不可用：分析继续，`researchStatus` 标记为 `unavailable`，相关证据降级为未验证，不伪造来源。
- IndexedDB 写入失败：结果仍可查看，但标记未保存；重试成功前不显示保存完成。
- 报告加载或打印失败：保留报告数据和重新触发入口，不删除历史。
- 旧数据模式不兼容：停止读取受影响记录并提示版本问题，不静默删除。

## 10. 可访问性与响应式要求

- 所有交互可通过键盘完成，并有清晰的可见焦点。
- 颜色不是等级、风险或证据状态的唯一表达方式。
- 正文对比度至少 4.5:1。
- 维度和置信度进度使用可访问名称与 `aria-valuenow`。
- 分析结束后把焦点移到新结果摘要。
- 触控目标不小于 44×44 像素。
- 打印输出在黑白环境中仍能区分等级和状态。

## 11. 测试与验收

开发使用测试先行：先写一个描述行为的失败测试并确认失败原因，再写最小实现使其通过。评分、证据上限、问题排序、差异说明和存储事务使用单元测试；工作区、比较和报告使用组件测试；创建、追问、刷新恢复、报告、对比和客户端密钥边界使用 Playwright。

完成前必须重新执行：

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run security:client
npm.cmd run e2e
git diff --check
```

没有新的有效密钥时，代码和模拟流程可以完成验证，但不能宣称真实 DeepSeek 调用已通过。真实验收还需要将新密钥放入未跟踪的 `.env.local`，执行最小 smoke 请求、一次浏览器项目评估和一次中文 A4 PDF 保存。聊天记录中出现过的密钥不写入仓库、测试、日志或命令记录，完成开发后应轮换。
